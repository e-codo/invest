# Моя стройка фундамента

Личный трекер долгосрочного портфеля: раз в месяц вписываете взносы по активам и стоимость портфеля из приложения брокера,
а приложение показывает прибыль, доходность, путь к цели, календарь взносов, график и аллокацию относительно стратегии.
Рубли, Мосбиржа. Вход по почте и паролю, у каждого пользователя свои данные.

Что и зачем в приложении, описано в [docs/BRIEF.md](docs/BRIEF.md). Внешний вид согласован по прототипу.

Стек: Next.js (App Router), TypeScript, Postgres, Drizzle ORM, vitest.

## Запуск локально

Нужен Postgres. Быстрый вариант: создать базу `invest` с пользователем `invest` (пароль `invest`) или взять любую свою.

```bash
npm install
cp .env.example .env.local   # задайте SESSION_SECRET и DATABASE_URL
npm run db:migrate           # создаёт таблицы
npm run dev
```

Открыть http://localhost:3000. Без действующей сессии все страницы ведут на `/login`, где можно создать аккаунт.
Сгенерировать `SESSION_SECRET`: `openssl rand -base64 48`.

## Как устроено

**Вход** (`src/app/actions/auth.ts`). Регистрация и вход по почте и паролю, без подтверждения почты и без восстановления пароля.
Пароль хранится только как хэш `scrypt` с уникальной солью (`src/lib/password.ts`). После входа выдаётся подписанная кука `session`
(HttpOnly, SameSite=Lax, Secure в production) на 30 дней, в ней id пользователя. Сессию проверяют `src/proxy.ts` (первая линия) и каждая
страница и действие через `requireUser()`, все запросы к данным фильтруются по этому id. Чтобы разлогинить всех, смените `SESSION_SECRET`.

**База** (`src/db/schema.ts`). Деньги хранятся целыми копейками.

- `users`, `settings` (план взноса, цель, стратегия, тексты), `assets` (до 5, доля в стратегии), `milestones`.
- `contributions` и `contribution_items`: взнос (дата) и его суммы по активам. В месяце их может быть несколько.
- `portfolio_values`: стоимость портфеля, одна на месяц.
- `coupons` и `reinvests`: купоны (во «вложено своих» не входят) и их реинвест в выбранный актив.
- `auth_attempts`: неудачные попытки входа и регистрации для ограничения перебора.

**Расчёты** (`src/lib/portfolio.ts`, чистые функции, покрыты тестами): вложено своих, прибыль, доходность за всё время, годовая доходность (XIRR,
от 3 месяцев истории), серия месяцев подряд, аллокация по деньгам, направленным в актив, и раскладка планового взноса (сумма равна взносу до рубля).

**Экраны.** Главная (`/`): стоимость и прибыль, путь к цели, календарь, график, аллокация, кнопка «+» для отметки месяца и правки месяца.
Настройки (`/settings`): активы (с переносом взносов при удалении), стратегия, план взноса, цель и вехи, тексты.

## Деплой на Vercel

Понадобятся аккаунты GitHub и Vercel. Деньги не нужны: подойдёт бесплатный тариф Hobby.

1. **Код.** Vercel выпускает в продакшн ветку `main`.
2. **Проект.** Add New → Project → репозиторий `e-codo/invest`. Framework Preset: Next.js. Команда сборки `vercel-build` уже в `package.json`.
3. **База.** Storage → Create Database → Neon (Postgres) → подключить к проекту. Vercel сам добавит `DATABASE_URL` и `DATABASE_URL_UNPOOLED`. Делайте это до первой сборки: она применяет миграции.
4. **Переменные окружения** (Settings → Environment Variables), для Production: `SESSION_SECRET` (случайная строка, `openssl rand -base64 48`).
   Переменная `APP_PASSWORD` из прежней версии больше не нужна, её можно удалить.
5. **Deploy.** Откройте адрес проекта и создайте аккаунт.

Внимание: миграция `0003_v2` удаляет таблицы прежней версии вместе с данными (по договорённости, тестовые данные не переносятся).

Советы:

- Регион функций (Settings → Functions) лучше выбрать тот же, что у базы Neon.
- Базу лучше подключать только к Production, чтобы Preview-сборки не писали в боевые данные.
- Резервные копии: посмотрите в настройках Neon, за какой срок можно восстановить данные.

## Безопасность

- Пароли только в виде хэша с солью. Вход и регистрация без подтверждения почты: чужой адрес можно занять раньше владельца, пароль нельзя восстановить.
- Перебор ограничен: 5 неудачных попыток с одного адреса или для одной почты закрывают вход на 15 минут. Регистраций с одного адреса не больше 5 в час.
- Заголовки безопасности заданы в `next.config.ts`, поисковики отключены.
- Секреты хранятся только в переменных окружения, в репозитории их нет.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Сборка падает на миграциях | Подключена ли база, есть ли `DATABASE_URL` для Production |
| «Сервис временно недоступен» | Заданы ли `SESSION_SECRET` (от 32 символов) и `DATABASE_URL` |
| После входа снова просит войти | `SESSION_SECRET` изменился между запросами или у экземпляров разные значения |
| Слишком много неудачных попыток | Подождать 15 минут |
